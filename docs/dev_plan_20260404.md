## 一、背景与目标

### 1.1 背景

synneu.io 在完成 Git 笔记管理基础功能（V1 规划）后，按原计划逐步集成 AI Agent 能力。
本次集成目标为 **OpenClaw v2026.03.24**，它是一个个人 AI 助手网关（Gateway），支持多渠道、多模型，
并已具备移动节点（Node）接入机制（iOS/Android）。

### 1.2 集成策略

**在 synneu.io 现有工程中新增独立 Feature 模块**，不新建项目，不破坏现有功能。
OpenClaw 相关页面作为 synneu.io 的新功能入口，与笔记、项目模块平级，共享状态管理、路由、主题。

### 1.3 核心功能目标

| 功能域 | 说明 |
|---|---|
| 会话（Chat Sessions）| 与 AI 对话，支持历史记录、流式响应 |
| AI 任务执行（Agent Jobs）| 发起 AI 任务、查看执行状态与结果 |
| 状态监控（Monitor）| Gateway 健康、渠道连接状态、日志流 |
| 配置管理（Config）| 查看与编辑 Gateway 配置 |

## 二、OpenClaw Gateway 协议说明

OpenClaw Gateway 以 **WebSocket JSON 帧协议**暴露所有功能，默认端口 `18789`。

### 2.1 连接流程

```
1. App → WebSocket 连接 ws://<gateway_host>:18789
2. App → 发送 connect 帧（含 token + nodeId + platform）
3. Gateway → 返回 hello.ok（连接建立成功）
4. 此后：双向 request/response 帧 + Gateway 主动推送 event 帧
```

### 2.2 节点配对（首次使用）

```
App → node.pair.request（nodeId, platform:"android"/"ios", caps:[...]）
Gateway 控制台 → 审批配对请求
App ← node.pair.verify（token）→ 本地持久化 token
```

### 2.3 核心 API 方法一览

| 功能域 | 方法 | 说明 |
|---|---|---|
| **会话** | `sessions.list` | 列出会话（支持标题/最新消息） |
| | `sessions.create` | 创建新会话 |
| | `sessions.send` | 向会话发送消息（支持附件） |
| | `sessions.messages.subscribe` | 订阅会话流式响应 |
| | `sessions.abort` / `sessions.reset` | 中止/重置会话 |
| | `sessions.usage` | Token 用量统计 |
| **AI Agent** | `agent` | 发起 AI 任务（含 prompt/model/thinking） |
| | `agent.wait` | 异步等待任务完成 |
| | `node.pending.*` | 接收 Gateway 下发的 exec 审批请求 |
| | `node.invoke.result` | 返回节点命令执行结果 |
| **状态监控** | `health` | Gateway 整体健康状态（30s 缓存） |
| | `status` | 状态摘要（含敏感信息需 admin scope） |
| | `channels.status` | 各渠道（Telegram/WhatsApp 等）连接状态 |
| | `logs.tail` | 实时日志流 |
| **配置** | `config.get` | 获取当前配置（YAML/JSON） |
| | `config.patch` | 增量更新配置（带 baseHash 防冲突） |
| | `config.schema` | 获取配置 JSON Schema（用于表单渲染） |
| **其他** | `models.list` | 可用模型列表 |
| | `agents.list` | Agent 配置列表 |

## 四、各模块详细设计

### 4.1 Gateway 连接层（`data/gateway_ws_service.dart`）

**职责：** 封装 WebSocket 连接生命周期与 JSON 帧协议，上层只调用业务方法。

关键设计：
- 单例 Service，通过 Riverpod `Provider` 注入全局
- 维护连接状态枚举：`disconnected` / `connecting` / `connected` / `error`
- 请求/响应帧匹配：每个请求带唯一 `id`，用 `Completer<Map>` 等待对应响应
- 事件帧（server push）通过 `StreamController` 分发给订阅者
- 断线自动重连（指数退避，最大 30s）
- 需新增依赖：`web_socket_channel: ^3.0.1`

```dart
// 帧格式参考（OpenClaw protocol/schema/frames.ts）
// Request:  {"id":"uuid","method":"sessions.list","params":{}}
// Response: {"id":"uuid","ok":true,"result":{...}}
// Event:    {"event":"chat.delta","payload":{...}}
```

### 4.2 Gateway 配置与配对页（`gateway_setup_page.dart`）

**首次使用流程：**
1. 用户输入 Gateway 地址（如 `192.168.1.100:18789`）
2. App 生成唯一 `nodeId`（UUID），调用 `node.pair.request`
   - `platform`: `"android"` 或 `"ios"`
   - `displayName`: 设备名
   - `caps`: `["chat", "agent"]`（声明支持的能力）
3. 用户在 Gateway 控制台（Web UI）点击审批
4. App 收到配对成功事件 → 获取 token → `shared_preferences` 持久化
5. 跳转至 OpenClaw 主页

**多 Gateway 支持：** 本地存储多个配置（地址 + token），支持切换当前激活 Gateway。

### 4.3 会话/聊天模块（`chat/`）

**聊天列表页（`chat_list_page.dart`）：**
- 调用 `sessions.list`（`includeDerivedTitles: true, includeLastMessage: true`）
- 展示：会话标题、最新消息预览、时间戳
- 支持：新建会话、下拉刷新

**聊天详情页（`chat_detail_page.dart`）：**
- 进入时调用 `sessions.messages.subscribe` 开始订阅
- 接收 `chat.delta` event → 字符级增量追加到气泡（流式打字效果）
- 发送消息调用 `sessions.send`（`key`, `message`）
- 支持：中止生成（`sessions.abort`）、长按消息复制
- Markdown 渲染（需新增依赖 `flutter_markdown`）
- 显示 `thinking` 内容（可折叠区域，区分推理过程与最终回答）

**Riverpod 状态：**
```dart
// 会话列表
final sessionListProvider = AsyncNotifierProvider<SessionListNotifier, List<ChatSession>>();
// 单个会话消息流
final chatStreamProvider = StreamProvider.family<ChatDelta, String>((ref, sessionKey) {...});
```

### 4.4 AI 任务模块（`agent/`）

**任务发起页（`agent_page.dart`）：**
- 输入 prompt（多行文本框）
- 选择 Agent（从 `agents.list` 获取）、模型（从 `models.list` 获取）
- thinking 级别选择（none / low / high）
- 点击"执行"→ 调用 `agent` 方法 → 获得 `runId`
- 自动跳转到任务状态页

**任务状态页（`agent_result_page.dart`）：**
- 调用 `agent.wait`（轮询或 SSE）追踪 `AgentRunSnapshot`
- 状态展示：`running` 动画 → `ok` 绿色 ✓ / `error` 红色 ✗ / `timeout` 黄色
- 展示任务开始/结束时间、耗时
- 结果内容 Markdown 渲染（从对应 session 读取）

**Exec 审批推送（节点命令）：**
- Gateway 通过 `node.pending` 推送待处理工作（类型：`status.request` / exec-approval）
- App 收到后展示本地通知或页内 Banner
- 用户批准/拒绝 → 调用 `node.invoke.result` 回传结果

### 4.5 状态监控模块（`monitor/`）

**监控看板页（`monitor_page.dart`），分区展示：**

```
┌─────────────────────────────┐
│  Gateway 健康状态            │  ← health（30s 自动刷新）
│  ● 正常 / ✗ 异常            │
├─────────────────────────────┤
│  渠道连接状态                │  ← channels.status
│  Telegram ●  Slack ●  ...  │
├─────────────────────────────┤
│  模型/Token 用量             │  ← sessions.usage（柱状图）
│  [今日] 12,430 tokens       │
├─────────────────────────────┤
│  实时日志                    │  ← logs.tail（滚动列表）
│  [INFO] agent run started   │
│  [WARN] model failover ...  │
└─────────────────────────────┘
```

- 日志流支持级别过滤（INFO / WARN / ERROR）
- 需新增依赖：`fl_chart: ^0.70.0`（用量图表）

### 4.6 配置管理模块（`config/`）

**配置页（`config_page.dart`）：**
- 调用 `config.get` 获取当前配置（YAML 字符串）
- 只读模式：代码块展示，支持复制
- 编辑模式：调用 `config.schema` 获取 JSON Schema → 渲染动态表单
  - 字符串字段 → `TextField`
  - 布尔字段 → `Switch`
  - 枚举字段 → `DropdownButton`
  - 敏感字段（`sensitive: true`）→ 密码框 + 遮蔽显示
- 保存时调用 `config.patch`（传入 `baseHash` 防止冲突覆写）

## 八、关键风险与应对

| 风险 | 影响 | 应对措施 |
|---|---|---|
| Gateway 在局域网外不可达 | 高 | 支持自定义端口 + 提示用户配置 Tailscale/反向代理；文档说明网络要求 |
| WebSocket 在 Android/iOS 后台被系统回收 | 中 | 进入后台时主动断开，前台恢复时重连；不依赖长连接做推送，改轮询补偿 |
| `chat.delta` 流式帧频率过高导致 UI 卡顿 | 中 | 限流：每 50ms 合并一次 delta 批量更新 `setState` |
| `config.schema` 结构复杂导致表单渲染困难 | 中 | V1 仅渲染基础类型（string/bool/enum），嵌套对象退化为 JSON 文本编辑 |
| Gateway token 泄露风险 | 高 | Android 用 EncryptedSharedPreferences，iOS 用 Keychain（通过 `flutter_secure_storage`）|
| OpenClaw 协议版本升级破坏兼容性 | 低 | 锁定对接版本 v2026.03.24，升级时单独评估 |
